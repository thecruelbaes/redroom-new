# Сканер соответствия 152-ФЗ

Внутренний инструмент. Не SaaS, не продукт для продажи, не юридический аудит.
Задача — превратить список сайтов в список поводов для конкретного разговора.

Живёт в `tools/` внутри репозитория сайта студии и от него полностью независим:
свой `package.json`, свой `tsconfig.json`, из сборки Next.js исключён.

## Запуск

```bash
cd tools/pdn-scanner
npm install

# один сайт
npx tsx src/cli.ts example.ru --niche medicine

# пачка из CSV (колонки domain, org_name, niche, inn)
npx tsx src/cli.ts --input domains.csv --out raw_results.json

# реестр норм и статус их проверки
npx tsx src/cli.ts --law
```

Если браузер уже установлен отдельно (контейнер, CI):

```bash
PDN_CHROMIUM_PATH=/opt/pw-browsers/chromium PDN_NO_SANDBOX=1 npx tsx src/cli.ts example.ru
```

Проверка на контролируемых страницах, без обхода чужих сайтов:

```bash
node fixtures/serve.mjs &
npx tsx src/cli.ts http://127.0.0.1:8787/bad/ http://127.0.0.1:8787/good/ http://127.0.0.1:8787/tricky/
```

## Что выяснилось при проверке норм — и почему это изменило сканер

Проверка правовой части спецификации дала результат, который меняет не код, а
то, что вообще имеет смысл говорить клиенту.

**1. Главный аргумент спецификации не подтвердился.** Утверждение «Google
Analytics = трансграничная передача = ст. 13.11 ч. 8 = до 6 млн» неверно в
каждом звене: ч. 8 — это локализация, а отдельного состава за нарушение порядка
трансграничной передачи в КоАП нет вовсе; такие нарушения квалифицируют по
ч. 1/ч. 2, то есть как обычное отсутствие основания для обработки. Поэтому
`CK-04` в коде — не нарушение, а признак: он не даёт severity, не весит в
скоринге и не идёт в письмо как обвинение. Его роль — вопрос о том, где
хранятся данные, из которого выходит локализация с настоящей суммой.

**2. Суммы за политику были перепутаны колонками.** По ч. 3 ст. 13.11 у ИП
10–20 тыс., у юрлица 30–60 тыс.; варианта «60–100 тыс.» в этой части нет.
Практический вывод: для ИП штраф здесь меньше стоимости работ по устранению,
и строить письмо вокруг одной этой нормы арифметически бессмысленно.

**3. Уведомление РКН — два разных состава, которые все путают.** Неподача
уведомления *об обработке* — ч. 10 (юрлица 100–300 тыс.). Неуведомление
*об утечке* — ч. 11 (1–3 млн). Вторичные источники регулярно приписывают
миллионы первому составу. Разница принципиальна: если назвать в письме
завышенную сумму, юрист клиента поймает это на первом созвоне.

Всё это зафиксировано в `src/legal.ts` — не как комментарии, а как данные с
полем `confidence`. Отчёт обязан звать `assertReportable()` перед печатью любой
ссылки на закон, и норма со статусом ниже `verified` в клиентский документ
физически не попадёт.

> **Не закрытый долг.** Сеть в окружении, где собирался модуль, блокирует
> consultant.ru, garant.ru и pravo.gov.ru. Проверка сделана по нескольким
> независимым вторичным источникам с перекрёстной сверкой — это не то же самое,
> что сверка с текстом кодекса. Перед первым письмом клиенту каждую запись надо
> открыть в КонсультантПлюс с обычной машины и проставить `checkedAt`.
> Работы на полчаса. `npx tsx src/cli.ts --law` печатает список того, что ждёт
> сверки, и запуск сканера напоминает об этом в конце каждого прогона.

## Четыре состояния вместо двух

Требование «лучше недосказать, чем ошибиться» невыполнимо, пока результат
проверки бинарный: любая неудачная детекция превращается в обвинение.

| Статус | Значение | Весит в скоринге | Идёт в письмо |
|---|---|---|---|
| `pass` | требование выполнено | нет | нет |
| `fail` | требование нарушено | да | да, кроме `low` |
| `unknown` | проверить не удалось | нет | нет |
| `na` | проверка неприменима | нет | нет |

Дополнительно считается **уверенность скана** — доля проверок, давших
определённый ответ. Лид с высоким баллом и уверенностью 60% получает вердикт
`RESCAN`, а не «горячий»: показывать клиенту отчёт, где треть пунктов не
проверена, нельзя.

## Отличия от исходной спецификации в детекции

**Предотмеченный чекбокс нельзя ловить через `defaultChecked`.** Это свойство
отражает HTML-атрибут `checked`. Контролируемый React-чекбокс с начальным
состоянием `true` имеет `checked === true` и никакого атрибута — то есть
проверка молчала бы ровно на том случае, ради которого написана. Читается живое
свойство на момент отрисовки; фикстура `tricky/` закрывает этот случай.

**Отсутствие `action` у формы — не признак отправки на чужой домен.** Формы на
`fetch` (весь современный фронтенд, включая сайт студии в этом же репозитории)
не имеют `action` вовсе. Наивное сравнение выдало бы «форма уходит налево» для
нормального сайта, поэтому такой случай уходит в `unknown` и разрешается по
сетевым запросам.

**`waitUntil: 'networkidle'` не используется.** Playwright сам его не
рекомендует, а на живых сайтах он не наступает: виджеты чатов, поллинг и
вебсокеты держат сеть занятой до таймаута. Вместо него — `domcontentloaded`,
прокрутка страницы (без неё не стартуют ленивые счётчики) и ожидание паузы
в запросах с жёстким потолком.

**INF-04 намеренно возвращает `unknown`.** Требование локализации касается
места хранения базы, а не места отдачи HTML. Вывод «зарубежный IP → нарушена
локализация» неверен юридически. IP фиксируется как факт, вывод остаётся
человеку; содержательнее INF-05 — куда фактически уходят данные форм.

**Отсутствие cookie-баннера не является нарушением.** Нормы, прямо обязывающей
его показывать, в 152-ФЗ нет. В отчёте — только раздел замечаний, без ссылки на
закон и без суммы.

## Гигиена обхода

`robots.txt` уважается, при любой неоднозначности обход считается запрещённым.
User-Agent честный, с контактом, только ASCII — кириллица в заголовке роняет
`fetch`. По умолчанию не чаще одного запроса в 2 секунды, параллелизм 3.

## Чего ещё нет

- Хранилище: сейчас JSON, в спецификации SQLite с таблицей задач.
- Генерация PDF-отчёта — следующий шаг после сверки норм.
- `ORG-01` — сверка ИНН с реестром операторов РКН. Это самая полезная проверка
  из всех: она не требует доступа к сайту, даёт бинарный ответ без ложных
  срабатываний, и устранение по ней тоже не требует доступа к сайту.
- `DOC-05` сейчас всегда `pass`: закон не требует именно отдельного документа
  согласия, поэтому его отсутствие нарушением не считается.
